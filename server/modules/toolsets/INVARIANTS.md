## INV-8471 — Tool sets — edits that break them: a set reaches a CLI only through `setMcpServers` with the full on-set map; an in-process SDK server rides every call

Behaviour: MAN-8495, MAN-8502 and MAN-8503 (the seam; MAN-8502 lists tool sets among `planLiveChanges`' live settings), MAN-8497 (the module map). The doors side is INV-8472. A set's servers reach a CLI through `Query.setMcpServers(map)` and nothing else; `map` is the chat's full on-set map on every call, less the two named exceptions below (a retry's first call, a base-named server).

| Edit | Breaks | Why |
|---|---|---|
| Put a set's servers in the launch's `mcpServers` option (`resolveSdkOptions`, `sdkOptions.mcpServers`), or call `toggleMcpServer` for one | the launch map is compared by `planLiveChanges`: a switch reads as "the MCP server configuration changed" and replaces the chat's process. `toggleMcpServer` writes `disabledMcpServers` into the project's `~/.claude.json` entry, shared by every session in that folder (header of `claude-toolset-seams.ts`) | one path makes on, off, a fresh process and a re-adopted one the same code |
| Make a tool-set difference a respawn reason in `planLiveChanges` (`chat-process.ts`), or leave `changes.toolsets` out of `applyChanges` | every switch retires the chat's process: `retire` interrupts the turn, and a background task still running at the EOF dies with the CLI | tool sets are a live setting: `changes.toolsets = next.toolsets !== null && next.toolsets !== live.toolsets`, applied by `setMcpServers` (MAN-8502) |
| Send `setMcpServers` a delta — only the switched set's servers, or a map missing any of the chat's other on-sets | the call REPLACES the dynamically-added servers it owns (SDK `Query.setMcpServers`): every on-set left out is disconnected | `createToolsetSync` hands the hook's full map to every call; `servers: null` sends nothing |
| Give the retry's first call the full map (drop `without` in `runOnce`) | the CLI treats a repeat of an identical map as a no-op and stops reporting a failed server: it is never reconnected | a server in `failedNames` is left out of call 1 and put back by call 2 (the full map); `mergeResults` joins both (MAN-8503) |
| Remove `baseServerNames` / `shapeForCli`'s rejection, or let a set's server take a launch-option server's name | measured on Claude Code 2.1.301: a `setMcpServers` naming a launch-option server TAKES THE NAME OVER, and the call that later omits it removes the operator's server | `shapeForCli` leaves such a server out of every call and reports it in `errors`. It covers the launch `mcpServers` option only: a base server from a settings file or a plugin cannot be named here (unmeasured) |
| Give a chat launch an in-process SDK server (`type: 'sdk'`, `createSdkMcpServer`) and not re-pass it in the `sendable` map of every `setMcpServers` call (`runOnce`, `claude-toolset-seams.ts`) | `setMcpServers` also replaces every in-process SDK server. Measured by the operator 2026-10-15: a call passing only the new set tore down the SDK server hosting the switch tool in the middle of its own call ("Connection closed") | no chat launch carries one today and none is added; the day one does, it rides every call |
| Accept `type: "sdk"` in `toolsets.local.json` (`serverDefect`) | a file cannot define an in-process server; it would be handed to `setMcpServers` as a stdio/http shape it is not | the reader refuses every `type` but `stdio`, `http`, `sse` |

## INV-8472 — Tool set doors — edits that break them: no server config from a caller, the guard first, one credential per chat

Behaviour: MAN-8499 (the doors, the guard, the credential), MAN-8500 (`switchSet`, `launchFor`), MAN-8501 (the command). The mechanism side is INV-8471. A caller names a set and nothing else; the credential is one chat's.

| Edit | Breaks | Why |
|---|---|---|
| Let a route, the command (`bin/toolset.mjs`) or the launch hook take a server config from a caller — a body field, an argument, an environment variable — or let `switchSet` accept `on` for a name the box file does not define | a chat's model defines a server: a command it names runs as the operator's user | the box file is the only definer; `on` of an undefined name is 404 `TOOLSET_NOT_DEFINED`; the command sends `{ claudeSessionId, action, set }` and nothing more |
| Mount `commandRouter` behind a path that skips `chatCredentialGuard`, or move the guard from the router's first middleware (`server/index.ts`, `toolsets.routes.ts`) | the command door answers an unauthenticated caller: any local process switches any chat's sets | the mount carries no `authenticateToken` on purpose (the command holds no user token); the guard is the router's first middleware, so no path of the router skips it |
| Put the operator's JWT, or any credential but `chatCredential(appSessionId)`, in a CLI's environment (`launchFor`), derive the credential without the `toolset:${appSessionId}` input, or compare it with `===` | a model holds the operator's login, one credential opens two chats, or the compare leaks timing | per-chat HMAC-SHA256 keyed by `JWT_SECRET`; `chatCredentialMatches` is `crypto.timingSafeEqual` after a length check (MAN-8992) |
| Answer an unknown session, a non-Claude chat and a wrong credential with different refusals (`chatCredentialGuard`) | a model learns which session ids exist | one answer: 401 `CHAT_CREDENTIAL_REFUSED` |
