## INV-9605 — Chat command doors — edits that break them: the guard first, one credential per chat, the account from the run, no edit or delete for a chat

Behaviour: MAN-8992 (the credential, the guard, the account of a chat, the link) and MAN-8993 (the notes command, its door and its skill) and MAN-9003 / MAN-9004 (the followups lane: its store, doors, command and widget); the toolset door's side is INV-8472. A chat acts through ONE credential, for ONE account, with the smallest set of verbs.

| Edit | Breaks | Why |
|---|---|---|
| Mount a command router (`/api/notes-cmd`, `/api/toolsets-cmd`, `/api/followups-cmd`, a new one) without `chatCredentialGuard` as its FIRST middleware, or move it later (`server/index.ts`, `notes.command-routes.ts`, `toolsets.routes.ts`, `followups.command-routes.ts`) | the door answers an unauthenticated caller: any local process reads and writes the operator's notes | the mount carries no `authenticateToken` on purpose (the command holds no user token); the guard is the only check there is |
| Give a new command a credential of its own, or derive `chatCredential` differently (a different prefix, key or input) | one more secret per chat, or every running chat locked out of every command door until its next process | the digest is already in each launched CLI's environment as `CLOUDCLI_TOOLSET_TOKEN`; the guard recomputes it, nothing is stored |
| Resolve the account of a chat from `userDb.getFirstUser()`, "the only user", a body field, the operator's JWT, or a guess when `accountOfChat` answers null | notes are written to or read from another account. `users` holds two accounts on this box (`verve`, id 1, the harness's; the operator's, id 2): the first user is the harness account, not the operator | `sessions` records no owner; the owner is the account the run was started under (`chatRunRegistry` writer, else the live host's meta). No answer is a 403 `CHAT_ACCOUNT_UNKNOWN`, never a default |
| Add an `edit` or `delete` action to `notes.command-routes.ts`, a flag to `bin/notes.mjs` that rewrites a note, or a line in the `notes` skill that does | a model rewrites or throws away the operator's notes | the door is list, show and add: a chat can read when he asks and add what he asks for; the rest stays his, in the Notes tab |
| Let the command door call anything but the `NotesService` the tab's routes call (a second validator, a direct `notesDb` write) | a title of 201 characters, or an empty one, lands from a chat and not from the tab; a note added by a chat sends no `notes_changed`, so an open Notes tab never shows it | the validation and the frame live in the service, once |
| Make `/api/notes` accept the chat credential, or `/api/notes-cmd` accept the operator's JWT | the two doors' guards blur: a model holding a chat credential reaches every route of the tab, or a token with every account behind it opens the command door | one guard per mount |
| Make `/api/followups` accept the chat credential, or `/api/followups-cmd` accept the operator's JWT; or read the chat from the body of `/api/followups-cmd` instead of `chatAppSessionOf(response)` | a model reads, files or closes another chat's next steps, or a token with every account behind it opens the command door | one guard per mount, and the chat is the credential's: every verb of the door is scoped to it. An id of another chat is a 404 |
| Add a delete or reopen action to `followups.command-routes.ts` or `bin/followups.mjs` | a model drops or reopens what the person has ticked or not yet seen | the door is list, add, done. An item leaves only with its chat; the person unticks in the widget |
| Put `FOLLOWUPS_SIGNAL` back into the always-on `SURFACE_PROMPT_APPEND`, or lead a launch with it when the launch carries no chat credential (`surface-signal.ts`, `claude-runtime.provider.js`) | a chat on a Cerberus node (or one with no app session id) is told to run a command it has no credential for: `followups` answers "not a CloudCLI chat" every turn, and the widget reads empty over replies that ask questions | the instruction depends on the credential the toolsets hook hands out; `leadWithFollowupsSignal` is applied only when the launch's env carries `CLOUDCLI_TOOLSET_TOKEN` |
| Remove a session row by a path that skips the `followups` foreign key (a copy-and-rename rebuild of `sessions` with foreign keys off), or merge two session rows without `followupsDb.moveToSession(duplicate, survivor)` first | a chat's items vanish with the row the cascade removes, or hang on an id that no longer exists | the cascade is what deletes a chat's items on every delete path; a merge must move them before it deletes |
